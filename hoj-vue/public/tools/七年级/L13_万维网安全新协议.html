HTTP 为什么不安全？

HTTP 协议设计于 1990 年代，最初只为"传递学术论文"。它的内容完全是明文——就像寄一张明信片。

使用 HTTP 时，任何能截获网络通信的人（黑客、运营商、公共 WiFi 提供者）都能看到你的账号密码、聊天内容、银行卡号。

HTTPS = HTTP + 加密

HTTPS = HTTP over TLS/SSL。在 HTTP 之下加一层"加密信封"。

📮 HTTP（明信片）

  • 明文传输
  • 容易被监听
  • 容易被篡改
  • 无法确认对方身份
  • 浏览器显示"不安全" ⚠️

🔒 HTTPS（加密信封）

  • 加密传输
  • 监听到的是乱码
  • 篡改会被发现
  • 能验证对方身份
  • 浏览器显示"🔒 锁标"
📌 注意：HTTPS 不是新协议，本质还是 HTTP，只是在底层加了 TLS（Transport Layer Security）加密层。所有应用代码完全不用改。

HTTPS 怎么做到加密？

核心是"非对称加密 + 对称加密"的巧妙组合。

🔑
对称加密
加密和解密用同一把钥匙。速度快，但钥匙怎么安全送给对方？
🗝️
非对称加密
用公钥加密、私钥解密。公钥可以公开，私钥只服务器自己有。
🤝
混合方案
用非对称安全地交换一把对称密钥，之后用对称加密快速通信。

简化版 TLS 握手

  1. 浏览器：你好服务器，我想建立加密连接 🙋
  2. 服务器：发送数字证书（含公钥）+ 我的身份信息 📜
  3. 浏览器：验证证书→生成一个对称密钥→用服务器公钥加密发回 🔐
  4. 服务器：用自己的私钥解密，得到对称密钥 🔓
  5. 双方：从此用对称密钥加密通信 ✅

数字证书 = 网站的身份证

怎么证明这台服务器真的是 "www.taobao.com" 而不是黑客假冒的？答案是数字证书。

📜 数字证书由权威的证书颁发机构 (CA, Certificate Authority)签发，包含：网站域名、公钥、CA 签名、有效期等。

知名 CA 机构

  • 🌍 国际：DigiCert、Let's Encrypt（免费）、Sectigo、GlobalSign
  • 🇨🇳 国内：CFCA（中国金融认证中心）、GDCA、沃通、自主可控的"国密"证书

如何查看证书？

浏览器地址栏点击 🔒 锁标 → "证书有效" → 可以看到颁发者、有效期、加密算法。

⚠️ 警告：如果浏览器提示"证书无效"、"证书过期"、"域名不匹配"——千万不要继续访问！很可能遇到了钓鱼网站或中间人攻击。

为什么 HTTPS 普及如此重要

  • 保护隐私：支付、登录、聊天信息不再裸奔
  • 防止劫持：不会被运营商插入广告，不会被黑客篡改
  • 身份确认：避免钓鱼网站冒充正规网站
  • SEO 利好：搜索引擎优先收录 HTTPS 网站
  • 是法律要求：金融、政务、电商网站必须使用 HTTPS

更快的速度
加密和身份验证

✅ HTTPS 通过 TLS/SSL 层提供加密传输 + 数字证书身份验证。
2️⃣ HTTPS 中证书的作用不包括？
证明网站身份
包含网站公钥

✅ 证书的作用是身份验证和提供公钥，不能加速网站。事实上，HTTPS 因为多了握手，比 HTTP 略慢一点（不过现代优化下差异极小）。
3️⃣ 在公共 WiFi 下登录账号，应该选择？
随便什么 WiFi 都行
只用 HTTPS 网站
优先 HTTP 因为更快
断网最安全
✅ 公共 WiFi 容易被监听，访问 HTTPS 网站可以保证传输内容加密。注意检查浏览器地址栏的 🔒 锁标。

🎓 课堂总结

  • HTTP 明文传输，像明信片，不安全
  • HTTPS = HTTP + TLS，加上加密保护层
  • 混合加密：非对称传密钥 + 对称传数据
  • 数字证书由 CA 签发，证明网站身份
  • 当今互联网 95%+ 网站已经使用 HTTPS
